## Data model facts (verified in `api/migrations/`)

- `clients` (`001_init.sql`): `id, name, country, account_owner_id, deleted_at, spec_grades, spec_cup_profile, spec_moisture_max, spec_min_score, spec_notes, default_phyto_cert`. **`UNIQUE INDEX clients_name_lower_idx ON clients ((lower(name)))`** — soft-deleted rows still hold their name, so a rename into an existing name collides.
- `client_contacts.client_id` — `NOT NULL REFERENCES clients(id) ON DELETE CASCADE`.
- Rows pointing at a client via nullable `client_id uuid REFERENCES clients(id)`: `samples` (legacy, 001), `specialty_samples`, `bulk_samples`, `forwarding_samples` (002). Each ALSO carries a free-text receiver column (`receiver_company` / `client`) that is what the dashboard shows and what `all_samples_v.receiver` exposes.
- Polymorphic `events` table (`entity_type`, `entity_id`) — client history; helper `runWithEvent` / `entityEvents` in `api/src/lib/mutate.ts`.
- `consignments` don't reference clients.
- Contact merge-on-write already exists: `upsertContact()` in `api/src/routes/clients.ts` (matches on `lower(attention_to)` / `phone` / `lower(email)`, COALESCE-fills). Reuse it when folding contacts.
- Delete is soft (`clients.delete('/:id')` sets `deleted_at`).

## Prompt

> Build "merge duplicate clients" for the Sucafina sample-management system (feedback item #27; background + data-model facts in `docs/HANDOVER-merge-clients.md` — read it first, then `docs/feedback-status.md`, `api/src/routes/clients.ts`, `src/skills/client-book.skill.ts`).
>
> Scope, all four layers:
> 1. **API** — `POST /clients/:id/merge { source_ids: uuid[], name?: string }` (target = `:id`, sources fold INTO it), in one transaction: re-point `client_id` on `samples`, `specialty_samples`, `bulk_samples`, `forwarding_samples` from each source to the target; fold each source's `client_contacts` into the target via the existing `upsertContact()` (no duplicate people); COALESCE-fill target's `country`, `account_owner_id`, `spec_*`, `default_phyto_cert` from sources where the target is null; optionally rename target (respect the case-insensitive unique index — soft-deleted rows still hold names, so on collision with a soft-deleted row rename that row to `<name> (merged <shortid>)`); soft-delete sources with an `events` entry `merged_into <target id>` and one `merged` event on the target listing sources + counts. Also update the free-text `client` / `receiver_company` on the re-pointed sample rows to the target's name **only when** the old text equals a source's name (case-insensitive) — legacy free-text variants stay untouched. Refuse when target is a source, when any id is missing/deleted, or when merging an internal Sucafina office into an external client. Return `{ target, merged: [{id,name}], repointed: {specialty,bulk,forwarding,legacy}, contacts_folded }`. Add a `GET /clients/:id/merge-candidates` that lists other clients whose normalized name (strip punctuation, "ltd/oy/gmbh/co/ag/(new)…" suffixes, dates) matches — the dashboard and agent both use it. Vitest coverage in `api/test/clients-merge.test.ts` (happy path, contact fold no-dupe, name collision with soft-deleted row, refusal cases, events written).
> 2. **Dashboard** — on `ClientDetailPage`, a "Merge into…" action: pick target via the client search, preview counts (samples per book, contacts, candidates from `merge-candidates` pre-suggested), confirm, then navigate to the target with a toast. Merged (soft-deleted) sources disappear from `ClientsPage`. Follow existing patterns (`useRecords`, drawer/dialog components already in `dashboard-v2/src/components`); keep `registry.test.ts` green; `npm run build`.
> 3. **Agent** — new `merge_clients` tool in `client-book` skill: `{ target: id|name, sources: (id|name)[], new_name? }` → resolves names via `find_client` semantics (refuse on ambiguity — list candidates), calls the API, returns the summary. I can merge them into <fullest entry>"), and only merge on an explicit yes; always keep the entry that has an address as the target; echo the plan (target, sources, counts) and confirm before calling; never merge internal Sucafina offices into clients. Update `upsert_client`/`sample-intake` guidance so a "merge them" reply during intake routes to this tool instead of "I can't merge". Extend `scripts/tool-harness.ts` with a merge case run against a local API.
